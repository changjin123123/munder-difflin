# 보물공방 Windows 통합판

통합판 상단에는 **트레이딩 사무실**과 **보물공방** 두 탭이 있습니다. 회의에서 마이클의 최종 판정을 확인하고, 보물공방에서 빗썸 원화 현물과 빙엑스 USDT 무기한선물의 시세, 최신 뉴스, 모의 장부를 조회합니다. **전체 종목 모의 시작**과 **모의 중지**는 두 거래소를 함께 제어합니다. 장부의 현금과 손익은 KRW와 USDT로 나누어 표시합니다. 처음 실행하면 앱 데이터 폴더에 회의 작업공간을 준비하며, 기존에 지정한 작업공간이 있으면 그 폴더를 사용합니다.

Windows 배포 파일에는 Python과 보물공방 엔진이 들어갑니다. 마우스로 보물공방을 열면 엔진이 백그라운드에서 시작되며, 모의매매는 버튼을 눌렀을 때 시작합니다. 통합판이 소유한 엔진은 통합판 종료 시 감시를 중지하고 장부를 보존합니다. 통합판은 자체 Munder 설정 폴더를 사용합니다.

**트레이딩 사무실 → 뉴스 브리핑과 토론**에서 회의가 수집한 최근 24시간의 종목·시장 기사를 확인할 수 있습니다. 켈리가 블록미디어와 CoinDesk의 제목과 RSS 요약을 사건별로 묶습니다. 강세·약세 연구원과 마이클의 자막 옆 출처를 누르면 원문이 열립니다. 관련 기사, 사건 종합, 토론과 최종 심사의 인용이 확인되어야 회의 전용 장부에 모의 진입할 수 있습니다. 뉴스 기능 추가 전에 저장한 회의는 당시 기록으로 재생됩니다.

회의 순서는 Xiao 등의 [TradingAgents 원 논문 4절](https://arxiv.org/html/2412.20138v7)에서 가져왔습니다. 이 앱의 캐릭터와 엔진으로 구현하며, 분석과 강세·약세 토론 뒤 필리스가 계획을 제안합니다. 공격적·보수적·중립 심사역은 같은 계획과 앞선 의견을 차례로 검토하고, 케빈이 근거를 대조한 뒤 마이클이 결정합니다. 제안 가격은 당시 거래소 호가로 계산하고 승인된 모의 체결은 새 호가로 기록합니다.

기본 화면인 **10층 트레이딩 건물**에서 먼저 **전 종목 배정**을 누릅니다. 전체 거래쌍이 40팀에 배정되며, 같은 코인의 현물과 선물은 같은 팀이 담당합니다. 층과 팀을 고르면 담당 종목, 회의록, 발언과 모의 체결을 볼 수 있습니다. 건물 회의를 시작하면 40팀이 동시에 각자의 안건을 엽니다. 적격 후보가 없는 팀은 관망합니다. 팀당 범위는 1종목, 최대 3종목, 적격 종목 전부 중 선택합니다. 공개 자료는 최대 3건, 실제 AI 작업은 사무실의 엔진 슬롯 한도 내에서 나누어 실행합니다. 배정은 공개 시세만 사용하며, 시작 전에 최대 엔진 작업 수가 표시됩니다. 각 팀은 회의 때 현재 종목 자료를 새로 받습니다. 중지하거나 앱을 닫으면 새 회의를 시작하지 않습니다.

거래소별 공동 모의 원금은 빗썸 100만 원, 빙엑스 1,000 USDT입니다. 팀당 시작 예산은 각각 25,000원과 25 USDT이며, 한 건은 팀 시작 예산의 1/4(진입 수수료 포함)입니다. 체결 시 팀 가용액과 전체 가용액을 함께 확인하고 이미 보유한 코인에 추가 진입하지 않습니다. 거래소 주문은 모의 장부에만 기록합니다.

**양 거래소 전 종목 · 한 팀**을 고르면 이전의 순차 회의를 이용할 수 있습니다. 회차마다 두 시세판을 끝까지 읽고, 모의 대상이며 최근 2분 이내 가격·거래대금·등락률이 있는 종목을 비교합니다. 거래소 안에서 거래대금 순위 60%와 절대 등락폭 순위 40%를 반영합니다. 회차가 적었던 거래소와 최근 6회에 다루지 않은 코인을 우선하며, 같은 묶음에서 다룬 코인과 회의 장부에 보유 중인 코인은 건너뜁니다. 거래소 하나가 조회에 실패하면 화면에 표시하고 조회한 쪽으로 진행합니다. 회의록에는 비교 후보 최대 5개와 선정 당시 수치가 남습니다.

한 팀 모드의 기본값은 서로 다른 코인 최대 3개를 차례로 토론하는 모의 회의입니다. 시작 전에 종목 수와 간격을 바꿀 수 있으며 종목당 최대 14개 엔진 작업을 사용합니다. **종목 직접 지정** 또는 보물공방 시세판에서 종목을 클릭하면 개별 회의를 열 수 있습니다.

### 5개 조 정기 대회와 매매법 훈련

1·2층부터 9·10층까지 두 층씩 한 조입니다. **정기 대회 시작**을 누르면 첫 회차가 열리고, 이후 기본 6시간(선택 가능 1·6·24시간)마다 앱에서 반복합니다. 조 안에서 대표팀을 순환하고, 적격 후보가 없는 순번은 다음 팀에 넘깁니다. 5개 대표팀이 각자 새 13인 회의를 엽니다. 회차당 최대 70개 회의 작업과 손실 복기 최대 5개 작업을 사용합니다.

각 조는 회차마다 20만 원과 200 USDT로 대회를 시작합니다. 진입과 청산에는 거래소별 수수료·슬리피지를 반영합니다. 두 통화는 직접 합치지 않고 각 원금 기준 순수익률의 평균으로 순위를 매깁니다. 종료 시점에 열린 대회 포지션은 공개 호가로 정산합니다. 완료된 회차의 손실은 담당 조 매니저가 당시 회의록과 체결을 대조하고, 유지·진입액 축소·최소 손익비 상향·비용 대비 최소 익절폭 중 하나를 선택합니다. 검증된 변경은 다음 회차부터 해당 조에만 적용합니다. 앱 종료·장시간 관측 공백·수동 중지로 무효가 된 대회는 순위와 규칙 변경에서 제외합니다. 지난 회차를 한꺼번에 재실행하지 않습니다. 대회 장부는 건물 모의 장부와 독립입니다.

**층별 실현수익률과 매매법 훈련**에서 건물의 최근 30일 청산 성과를 봅니다. 새 건물 회의 시작 때 세 건 이상 청산하고 순익을 낸 팀을 수익률이 높은 층부터 찾습니다. 멘토의 중앙 손절폭·최소 손익비와 트레이더 의견을 다음 회의에 전달합니다. 멘토 층을 제외한 각 층에서 두 팀은 시험 규칙, 두 팀은 기존 규칙으로 진행합니다. 각 집단에 판정 세 건 이상, 합계 청산 네 건 이상, 미결제 시험 포지션 0건일 때 다음 건물 회의 시작 시 비교합니다. 시험 집단 실현수익률이 양수이고 기존 집단을 넘으면 채택합니다. 두 집단의 담당 종목은 서로 다릅니다.

### 빌드

1. 이 포크의 Node 20 및 Windows x64 Electron 32.3.3 의존성을 설치합니다. Electron과 호환되는 node-pty 및 better-sqlite3 바이너리가 필요합니다.
2. Windows x64 Python 3.12(Tk 포함)에서 `python tools/stage-treasure.py BOT_SOURCE.zip .treasure-stage`를 실행합니다. ZIP에는 최상위 폴더 하나와 `office_host.py`가 포함된 보물공방 소스가 있어야 합니다. 개인 데이터와 계정 설정은 포함하지 않습니다. 준비한 비공개 자산은 Git에서 제외됩니다.
3. `npx electron-vite build --mode treasure`, `npm run copy:main-assets`, `npx electron-builder --win portable --x64 --config electron-builder.treasure.yml --publish never`를 차례로 실행합니다. `treasure` 모드는 트레이딩용 화면만 묶습니다.

기본 장부 위치는 통합판 Electron userData 아래의 `treasure-engine/data`입니다. 기존 장부를 사용할 때는 같은 userData의 `treasure-location.json`에 `{"directory":"기존 보물공방 폴더의 절대 경로"}`를 저장한 뒤 앱을 다시 엽니다. 기존 보물공방이 그 장부를 사용 중이면 같은 Windows 사용자의 인증된 모의 전용 로컬 연결을 사용합니다. 화면에서 거래소 API 키를 요구하지 않습니다.
